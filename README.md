# LightOS

Лёгкий дистрибутив на базе **Debian 12 (bookworm)** для слабых ПК.

- **Рабочий стол:** XFCE с тёмной темой LightOS-Dark, композитор выключен
- **Установщик:** Calamares — язык, раскладка, пользователь, пароль, разметка диска
- **В системе:** Центр приложений, кнопка «Драйверы», кнопка «Оптимизация»,
  кнопка «Обновить LightOS» (через интернет, без флешки)
- **Объём:** ISO ~1.3 ГБ, установленная система ~4–5 ГБ

---

## На чём это проверено

Всё в этом репозитории тестировалось не на современном железе, а на
конкретном старом ноутбуке. Это важно: дистрибутив делался под него,
и все утверждения ниже — про эту машину, а не «в среднем».

**HP G62 Notebook PC**, выпущен в **2010 году**. BIOS от 09.06.2010.

| | |
|---|---|
| **Процессор** | Intel Core i3-350M @ 2.27 ГГц — 1 ядро, 2 потока |
| **Важно про CPU** | **без AVX**, без AVX2, без F16C, без FMA. Только SSE4.1/SSE4.2. Из-за этого часть игр и движков не запустится вообще, а не просто медленно |
| **ОЗУ** | 3.6 ГБ + 2 ГБ swap (файл подкачки на диске) |
| **Диск** | Hitachi HTS545025B9A300, 233 ГБ, **5400 об/мин** — HDD, не SSD |
| **Видеокарта** | Radeon HD 5430/5450/5470 (`1002:68e0`, кодовое имя **Park**) — дискретная |
| **Встроенная графика** | Intel GMA 945GM (`8086:0046`) — через неё шёл вывод, пока Radeon был без драйвера |
| **Wi-Fi** | Broadcom BCM4313 802.11bgn (`14e4:4727`) |
| **Проводная сеть** | Realtek RTL810xE |
| **Звук** | Intel 5 Series HD Audio + HDMI-аудио Cedar |

### Почему именно эта машина показательна

Здесь сходятся две редкие беды, из-за которых обычный десктоп
не показывает настоящего положения дел:

- **Дискретная видеокарта без драйвера.** `amdgpu` ищет прошивку
  PALADIN/PITCAIRN, которой для чипа Cedar/Park не существует, поэтому
  карта молчала, а система рисовала встроенной Intel. Нужен именно
  `radeon` и прошивки `firmware/radeon/CEDAR_*`.
- **Wi-Fi на Broadcom, который не работает на открытом драйвере.**
  BCM4313 отсутствует в таблице совместимости `b43`, а `firmware-brcm80211`
  нужных прошивок не содержит. Работает только проприетарный
  `broadcom-sta-dkms`.

Если дистрибутив тянет это — он тянет и остальное постарше.

### Чего ожидать на этом железе

| | |
|---|---|
| **Minecraft** (Java + OptiFine, настройки «Быстро», дальность 2–4 чанка) | 50–60 FPS вместо 15–25 |
| **Roblox** | запускается, но быстрее встроенной Intel не будет. Нужен OpenGL 3.3+ |
| **Чего ждать не стоит** | 60 FPS в Roblox и «в 10 раз быстрее прежней системы». i3-350M — это одно ядро 2010 года без AVX |

Реальный выигрыш даёт не «облегчение системы», а то, что **видеокарта
заработала впервые**. До правок она молчала.

### Проверено в этом релизе

- ISO собран (1 333 МБ), SHA256 совпадает
- Внутри образа: `radeon_drv.so`, прошивки `CEDAR_me/pfp/rlc/smc`,
  `pitcairn_*`, `broadcom-sta-dkms`, все 7 скриптов `lightos-*`
- `use_compositing=false` в skel, `/etc/xdg` и `/usr/share/lightos`
- Запись на флешку в режиме **DD** сверена: SHA256 `filesystem.squashfs`
  на флешке совпал с ISO побайтово

**Чего проверить без этой машины нельзя** — реальную скорость в играх
и то, какой именно драйвер Xorg подхватит карту. Для этого нужен
живой ноутбук, см. раздел ниже.

---

Это первый релиз, в котором система действительно работает на слабом железе.
Основные правки:

| Что | Было | Стало |
|-----|------|-------|
| Видеокарта | Radeon оставалась без драйвера, рисовала встроенная Intel | Ставится `radeon` + `firmware-amd-graphics`, определяется автоматически |
| Wi-Fi Broadcom BCM4313 | `firmware-brcm80211` (не содержит нужных прошивок) | `broadcom-sta-dkms` через DKMS |
| Композитор | Включён — 15–30% CPU впустую | Выключен в системном конфиге и в настройках нового пользователя |
| Сборка ISO | Падала на несуществующей опции `--bootstrap-keyring` | Опция удалена, сборка проходит |
| Релиз | Тег `latest`, не версия | Семвер `v1.0.0`, `v1.0.1` и т. д. |
| GitHub Actions | Обещан в README, но не существовал | Есть `.github/workflows/build.yml` |

## 1. Сборка ISO

### Вариант A. GitHub Actions (рекомендуется, ~15 минут)

Репозиторий содержит готовый воркфлоу. Открой вкладку **Actions** →
**Сборка LightOS** → **Run workflow**, укажи версию (например `1.0.0`)
и галочку публикации.

Результат появится в разделе **Releases**:
- `lightos-1.0.0.iso` — сам образ
- `lightos-1.0.0.iso.sha256` — контрольная сумма
- `lightos-update-1.0.0.tar.gz` — пакет для кнопки обновления
- `SHA256SUMS` — суммы пакета обновления

Ничего ставить локально не нужно.

Сборка идёт **в контейнере `debian:bookworm`**, а не на Ubuntu-раннере.
Это не просто прихоть: в Ubuntu 24.04 ставится live-build `3.0~a57`,
который при установке ядра качает
`dists/bookworm/Contents-amd64.gz` — а Debian перенёс Contents внутрь
компонентов, и по старому пути отдаётся 404. В bookworm живёт
live-build `20230502`, который этот файл не качает вовсе. Плюс мы
собираем bookworm и собираем на bookworm.

### Вариант B. Локально, на Debian

Собирать нужно на **Debian** (12 или 13) — не на Ubuntu: в Ubuntu
конфликтуют версии `syslinux` и `isolinux`, и сборка падает.

```bash
sudo apt update
sudo apt install -y live-build debootstrap debian-archive-keyring \
     xorriso isolinux syslinux-common squashfs-tools mtools dosfstools \
     parted fdisk grub-pc-bin grub-efi-amd64-bin ca-certificates

git clone https://github.com/danyavera123-art/lightos.git
cd lightos

# Собрать ISO в текущем каталоге
sudo ./build.sh

# Или в отдельный (так делает GitHub Actions)
sudo ./build.sh --output-dir ~/lightos-out
```

**Сколько времени занимает.** На слабом ноутбуке (2 ядра без AVX) — **2.5–5 часов**:
debootstrap 20–40 мин, установка ~770 пакетов 60–120 мин, сжатие squashfs с xz
40–90 мин. Температура процессора держится в пределах 60–70 °C, троттлинга нет,
но ноутбук при этом заметно греется — лучше собирать не в жару и не на коленях
и не одновременно с играми.

На современном CI-раннере та же сборка занимает около 15 минут.

Проверить, что всё в порядке, до долгой сборки:

```bash
bash -n build.sh                     # синтаксис
sudo ./build.sh --output-dir /tmp/x  # дойдёт до debootstrap — дальше Ctrl+C
```

### Вариант C. Локально, в контейнере (без установки на хост)

То же, что воркфлоу, но у себя — нужно только Docker:

```bash
git clone https://github.com/danyavera123-art/lightos.git
cd lightos

docker run --rm -it -v "$PWD:/build" debian:bookworm bash -c '
  export DEBIAN_FRONTEND=noninteractive
  apt-get update -qq
  apt-get install -y -qq --no-install-recommends git live-build debootstrap \
     debian-archive-keyring isolinux syslinux-common squashfs-tools xorriso \
     mtools dosfstools parted fdisk grub-pc-bin grub-efi-amd64-bin ca-certificates curl file
  SKIP_RELEASE=1 ./build.sh
'
```

### Вариант D. WSL2 на Windows

Работает, но в WSL нужно ставить зависимости вручную (см. вариант B),
а сборочные файлы живут в `~/lightos`, а не в `/mnt/c/...` — иначе сборка
в разы медленнее из-за обращений к диску Windows.

### Публикация в Releases вручную

```bash
# gh CLI: https://cli.github.com/
gh auth login

RELEASE_TAG=v1.0.0 sudo ./build.sh          # ISO уедет в Releases сам
./make-update-payload.sh 1.0.0 --publish     # и пакет обновления тоже
```

## 2. Запись на флешку и установка

1. Запиши ISO на флешку: **Rufus в режиме DD**, **balenaEtcher** или **Ventoy**.
   Режим Rufus — «DD Image Mode», не «ISO Image Mode».
2. Загрузись с флешки: **F12** (HP — одноразовое меню загрузки). Если
   флешки там нет, зайди в BIOS по **F10** → Boot Options → **USB Boot:
   Enabled**, поставь USB первым в Boot Order.
3. В меню загрузчика выбери любой пункт — все они рабочие.
4. В live-системе нажми иконку **«Установить LightOS»**.
   > Вход в live-режим автоматический: пользователь `lightos`, пароль `lightos`.
5. Пройдите мастер: язык → раскладка → пользователь и пароль → диск → установка.
6. По завершении нажми «Перезагрузить», вытащи флешку, загрузись с диска.

Образ гибридный: работает и в режиме UEFI, и в legacy BIOS/MBR.

### Если с флешки не грузится

**Экран пустой, ничего не происходит.** Значит BIOS не отдал носитель
загрузчику. Проверьте `USB Boot: Enabled` в BIOS и попробуйте
**F12** при включении. Отдельно стоит проверить **Legacy Boot**: часть
UEFI-прошивок 2010 года не берёт гибридный образ, зато legacy-режим
с `isolinux` работает всегда.

**Появляется меню загрузчика, текст на экране, и всё зависает.** Это уже
не загрузчик, а ядро: система монтирует `filesystem.squashfs` объёмом
1.3 ГБ по USB 2.0, и на HDD 5400 об/мин с небыстрой флешкой это занимает
долго — тем более что параметры загрузки содержат `quiet splash`, то есть
ошибки не видно. Помогает загрузка с копированием образа в ОЗУ:
выберите в меню пункт, в параметрах которого есть `toram`. На 3.6 ГБ
оперативной памяти образ занимает 1.3 ГБ — помещается.

> Если в меню нет подходящего пункта, образ можно перезаписать самому:
> параметры загрузки меняются в файле `isolinux/live.cfg` на флешке,
> а собрать изменённый ISO — `xorriso` (см. раздел о сборке).

## 3. Что делать после установки

**Первым делом — кнопка «Драйверы».** Без неё система может работать
на встроенной графике, даже если есть дискретная видеокарта.

Центр приложений (иконка на рабочем столе) → **«Драйверы (GPU / Wi-Fi / звук)»** →
скрипт определит ваше железо, покажет план и поставит нужное →
**перезагрузка**.

Проверить результат можно в терминале:

```bash
glxinfo -B | grep "OpenGL renderer"
```

Хорошие ответы: `Radeon HD 5430 (CEDAR)`, `AMD Radeon HD 5400M`.
Плохие: `Intel(R) HD Graphics` (не используется дискретная карта),
`llvmpipe` (программный рендеринг, игры будут очень медленными).

### Кнопки в Центре приложений

| Кнопка | Что делает |
|--------|-----------|
| Установить выбранное | Ставит программы из списка |
| Драйверы (GPU / Wi-Fi / звук) | Определяет железо и ставит драйверы |
| Оптимизация | Отключает композитор и анимации, настраивает zram и governor |
| Обновить LightOS | Обновляет LightOS через интернет |
| Обновить систему (пакеты) | `apt upgrade` |
| Диагностика | Показывает железо, драйверы, состояние композитора |
| Очистить кэш | `apt clean` + autoremove |

Те же команды доступны напрямую в терминале:

```bash
sudo lightos-drivers      # драйверы
lightos-drivers --detect # только определить железо, ничего не ставить
lightos-perf             # оптимизация
lightos-perf --status    # только посмотреть, ничего не меняя
sudo lightos-update      # обновить LightOS
sudo lightos-update --check     # есть ли обновление
sudo lightos-update --rollback  # откатиться на предыдущую версию
```

### Про игры

- **Minecraft:** Java-версия с OptiFine, настройки «Быстро», дальность прорисовки
  2–4 чанка. Ожидайте 50–60 FPS вместо 15–25.
- **Roblox:** запускается, если OpenGL 3.3 и выше (проверяется через
  `glxinfo -B | grep "OpenGL version"`). На дискретной карте с `radeon`
  будет заметно быстрее, чем на встроенной Intel.
- **Steam:** ставится через Центр приложений.

Чего ожидать **не стоит**: 60 FPS в Roblox и «в 10 раз быстрее текущей системы».
i3-350M — это 2 ядра 2010 года без AVX. Реальный выигрыш даёт не «облегчение
системы», а включение аппаратного ускорения видеокарты, которой раньше не
работало вообще.

## 4. Обновление LightOS

Кнопка **«Обновить LightOS»** забирает с GitHub архив ~100 КБ (не ISO целиком),
проверяет SHA256, распаковывает в `/usr/local/lib/lightos/` и обновляет
команды в `/usr/local/bin`. Резервная копия предыдущей версии лежит в
`/var/cache/lightos/` — откат работает отдельной командой.

Что эта кнопка **не** обновляет:

- ядро Linux — кнопка «Обновить систему»
- драйверы видеокарты — кнопка «Драйверы»
- установщик Calamares — только переустановка ISO

Выпуск новой версии (для того, кто поддерживает репозиторий):

```bash
# 1. Поднять версию в хуке
sed -i 's/^VERSION="1.0.0"/VERSION="1.0.1"/' \
    config/hooks/live/0350-lightos-scripts.hook.chroot

# 2. Собрать пакет обновления
./make-update-payload.sh 1.0.1 --publish
```

Готово — установленные системы подхватят обновление по кнопке.

## 5. Как это устроено

```
lightos/
├── build.sh                       # сборка ISO через live-build
├── make-update-payload.sh         # сборка пакета обновления (~100 КБ)
├── .github/workflows/build.yml    # сборка и публикация в CI
├── config/
│   ├── archives/                  # bookworm-security и bookworm-updates
│   ├── package-lists/             # пакеты: ядро, графика, XFCE, драйверы
│   ├── hooks/live/                # скрипты сборки
│   └── includes.chroot/           # файлы, попадающие в готовую систему
│       ├── etc/skel/              # файлы нового пользователя
│       ├── usr/bin/               # Центр приложений + lightos-*
│       └── usr/share/lightos/config/  # конфиги установщика и XFCE
└── README.md
```

### Скрипты системы

Все лежат в `config/includes.chroot/usr/bin/`, при сборке копируются
в `/usr/local/lib/lightos/bin/`. Команды для пользователя появляются в
`/usr/local/bin` уже без расширения `.sh`:

| Команда | Что делает |
|---------|-----------|
| `lightos-appcenter` | Центр приложений |
| `sudo lightos-drivers` | Определить железо и поставить драйверы |
| `lightos-perf` | Оптимизация под слабое железо |
| `sudo lightos-update` | Обновление LightOS из интернета |

| Файл | Назначение |
|------|-----------|
| `lightos-appcenter.sh` | Центр приложений: программы, драйверы, обновления |
| `lightos-drivers.sh` | Определение железа и установка драйверов |
| `lightos-perf.sh` | Отключение композитора, анимаций, настройка zram |
| `lightos-update.sh` | Обновление LightOS через GitHub Releases |
| `lightos-firstboot.sh` | Тема и обои при первом входе |
| `lightos-install-copy.sh` | Копирование live-системы на диск |
| `lightos-install-post.sh` | Настройка после установки, сборка DKMS-модулей |

`lightos-install-copy.sh` и `lightos-install-post.sh` — служебные, их зовёт
установщик Calamares. В `/usr/local/bin` они намеренно не попадают: запускать
их на работающей системе нельзя.

### Хуки сборки

| Файл | Что делает |
|------|-----------|
| `0000-fix-security-suite` | Исправляет несуществующий suite `bookworm/updates` |
| `0100-lightos-user` | Создаёт пользователя live-сессии |
| `0200-lightos-autologin` | Авто-вход и включение служб |
| `0300-lightos-desktop` | Иконка установщика на рабочем столе |
| `0350-lightos-scripts` | Складывает скрипты в `/usr/local/lib/lightos`, собирает DKMS |
| `0400-cleanup` | Ужимает ISO под лимит GitHub Releases |
| `0450-lightos-config` | Применяет конфиги поверх дефолтов пакетов |

### Экономия ресурсов

- XFCE, композитор выключен, анимации выключены
- zram на 50% ОЗУ + файл подкачки 1 ГБ
- `vm.swappiness=10` — старый swap не съедает оперативную память
- Лишние службы (Bluetooth, Avahi, CUPS) выключены в `lightos-perf.sh`
- Без LibreOffice и Thunderbird «из коробки» — ставятся через Центр приложений

## 6. Частые вопросы

**Не работает Wi-Fi после установки?**

Центр приложений → «Драйверы», затем перезагрузка. На Broadcom BCM4313/4321
открытый драйвер `b43` не работает в принципе (эти чипы есть не в таблице
совместимости), нужен проприетарный `broadcom-sta`. Скрипт ставит его и
добавляет `b43`/`bcma` в blacklist.

Если не заработало — проверьте в BIOS, что не выключен `Wireless LAN`.

**`glxinfo` показывает Intel, а у меня Radeon.**

Xorg не подхватил дискретную карту. Проверьте, видит ли её ядро:

```bash
lspci -k | grep -A3 'VGA compatible controller'
```

Если строки `Kernel driver in use:` нет — карта не привязана к драйверу.
Поставьте `sudo lightos-drivers` и перезагрузитесь.

**Не грузится с флешки?**

Проверьте порядок загрузки в BIOS и отключите Secure Boot.

**Хочу поменять раскладку или язык системы.**

Раскладка: `Alt+Shift` (настраивается в мастере). Язык: `sudo dpkg-reconfigure locales`.

**Сборка упала на `lb config`.**

Проверьте версию live-build: `lb --version`. Свежие версии (trixie)
не имеют опции `--bootstrap-keyring` — в `build.sh` она уже убрана,
но если у вас старая копия репозитория, обновитесь.

**ISO не публикуется — «превышен лимит».**

GitHub Releases ограничивает файл 2 ГБ. Если ISO перерос эту границу,
сборка честно сообщает об этом в конце. Проверить заранее:

```bash
ls -lh lightos.iso
```

**Как откатить обновление LightOS?**

```bash
sudo lightos-update --rollback
```

Резервная копия предыдущей версии лежит в `/var/cache/lightos/`.
